웹 빌더 2차 계산식/스킬 호환성 패치를 진행해줘.

중요:
- 현재 프로젝트의 기존 파일을 수정할 것.
- 파일 전체를 새 앱으로 갈아엎지 말 것.
- 캐릭터 포인트 계산, 액션 계산 로직은 바꾸지 말 것.
- 이번 패치는 스킬 계산식 검증/프리뷰/입력 보조 개선이 목적이다.
- npm run dev에서 오류 없이 실행되게 할 것.

수정사항:

1. 스킬 계산식에서 일반 다이스 표기를 지원해줘.

현재 d6, d20, 2d6 정도만 처리하는 것 같은데,
다음 형식을 모두 지원하게 해줘.

d6
d20
2d6
3d4
d100
XdY 형태의 일반 다이스

예:
5d8
10d6
1d100

프리뷰에서는 실제로 굴리지 말고 기대값으로 계산해줘.

공식:
dY = (Y + 1) / 2
XdY = X × (Y + 1) / 2

예:
d6 = 3.5
d20 = 10.5
2d6 = 7
3d4 = 7.5
d100 = 50.5

2. 계산식 프리뷰 함수 preview()를 일반화해줘.

현재처럼 d20, 2d6, d6만 문자열 치환하지 말고,
정규식으로 모든 XdY / dY를 찾아 기대값으로 변환하게 해줘.

예:
d20 + 랭크 + 감각
→ 10.5 + 랭크값 + 감각값

3d4 + 랭크 + 지능
→ 7.5 + 랭크값 + 지능값

d100 + 랭크
→ 50.5 + 랭크값

3. 계산식에서 곱셈 기호 ×를 사용할 경우 자동으로 *로 정규화해줘.

예:
랭크 × 2
→ 랭크 * 2

대상상태_출혈_수치 × 2
→ 대상상태_출혈_수치 * 2

출력되는 신청 텍스트에서도 가능하면 *로 정규화되게 해줘.

5. formulaProblems()를 확장해줘.

계산식에서 다음은 오류로 보지 말 것:
- 숫자
- + - * / 괄호
- 일반 다이스 표기 XdY / dY
- 랭크
- 스탯명
- 기능명
- 숙련명
- 현재체력 / 최대체력 / 이면침식 / 일상점
- 상태_ 로 시작하는 변수
- 대상상태_ 로 시작하는 변수
- 스택_ 로 시작하는 변수
- 대상스택_ 로 시작하는 변수

단, 아래는 경고로 표시해줘:
- 계산식이 비어 있음
- 알 수 없는 변수
- 괄호 짝이 맞지 않음
- 연산자로 끝남
- 연산자가 연속됨

6. 대상상태_ 또는 대상스택_이 계산식에 들어가면 오류가 아니라 경고를 표시해줘.

경고 문구:
"이 계산식은 대상 지정이 필요합니다. 사용 예: !스킬 스킬명 대상:대상별명"

이건 신청을 막는 오류가 아니라 운영/사용 안내 경고다.

7. 상태_ / 대상상태_ / 스택_ / 대상스택_ 변수는 프리뷰 계산에서는 0으로 처리해줘.

이유:
웹 빌더에서는 실제 전투 중 상태/스택 값을 알 수 없기 때문이다.

단, 프리뷰 아래에 안내를 표시해줘.

문구:
"상태/스택 참조 변수는 실제 사용 시 DB의 현재 값을 참조합니다. 빌더 프리뷰에서는 0으로 계산됩니다."

8. 현재체력 / 최대체력 / 이면침식 / 일상점 같은 고급 변수는 프리뷰에서 임시값 0으로 처리하거나, 안전한 기본값으로 처리해줘.

추천:
현재체력 = 0
최대체력 = 0
이면침식 = 현재 캐릭터의 이면침식 값
일상점 = 0

그리고 안내 문구를 표시해줘.

문구:
"고급 변수는 캐릭터 DB의 숫자형 필드를 참조합니다. 운영진 검수 대상입니다."

12. 효과 없음은 오류가 아니어야 한다.

효과는 선택 항목이다.

13. effectProblems()는 유지하되, 자유 입력 효과는 "오류"가 아니라 "운영진 수동 검수 대상" 경고로만 표시해줘.
